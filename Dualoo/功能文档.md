# Dualoo Functional Specification

App: **Dualoo** · CSV full name: **Dualoo - Crisp & Opposite** · Pack: `h5_swift_shell` (WKWebView shell + H5 vault) · Track: Casual Lifestyle · Depth tier: **L2 (control)** · Interaction topology: **T8_reminder_ring (Reminder ring)**

This Screen Inventory and rule set is authoritative for all later steps (`agent.design` → `agent.html` → `agent.shell` → `agent.h5`). Every listed route, rule, and capability is a MUST-implement contract.

---

## App Theme & Angle

Dualoo turns abstract vocabulary into tiny photo workouts. Every session starts with an antonym prompt pair drawn from a seeded deck — “Giant ⟷ Tiny”, “Wet ⟷ Dry”, “Chaos ⟷ Order”. The player walks out, shoots one real frame for each side through the native camera bridge, then rates how strongly each frame speaks for its opposite on a Dual Rail Board. A Contrast Score grades the duel; grade-S/A pairs are vaulted as Winning Pairs into the Opposites Vault; any vaulted pair becomes a crisp Before–After Strip saved to the system Photos album for concept drilling and sharing. The practice rhythm is driven by a rolling 7-day Drill Ring (reminder ring): wind it, complete today's duel, keep the streak. Everything runs offline on-device with no account, no cloud sync, and no social feed — the audience is young people who train concepts, attention, and composition with their camera.

- **Topology id: `T8_reminder_ring` (Reminder ring).** The home surface is the Drill Ring: a rolling 7-day ring ledger whose segments carry per-day drill state (`pending / in_progress / done / missed`) and mediate the daily reminder loop in-app.

- **Secondary modules:** today drill card (prompt preview + statuses), weekly stat footnote, dedicated coin/quota sheets.

## Business Rules Engine

Every rule states: trigger · rule · conflict policy · user-visible feedback.

- **BR-01 — Deck draw & no-repeat window.** Trigger: Wind-Up Draw release (PW step 4). Rule: candidates = seeded cards whose `lastDrawnAt` is null or older than 14 days, weighted toward `difficulty` not yet played this week. Conflict: if every card sits inside the window, the window shrinks day-by-day until at least one card qualifies — a draw never fails for repetition. Feedback: ring spring-back, shuffle shimmer, card flip showing the pair + difficulty pips.
- **BR-02 — Free draw quota.** Trigger: draw resolution. Rule: 3 free draws per local calendar day; `freeDrawsLeftToday` resets at midnight. Conflict: exhausted → coin sheet “12 coins for this draw” before the session is created; insufficient balance → deep link into Store (SW-B resumes at PW step 4 after top-up). Feedback: free-counter chip on the ring, coin sheet with new-balance preview.
- **BR-03 — One active session.** Trigger: draw while a non-terminal session exists (`drawn / left_captured / right_captured`). Rule: no second active session per device; a resume sheet offers “Resume {leftConcept} ⟷ {rightConcept}” or “Discard & draw anew”. Conflict: discard tombs the session as `discarded` (frames kept on disk for the audit trail), then a fresh draw runs under BR-01/BR-02. Feedback: resume sheet names the pending pair and its age.
- **BR-04 — Frame-to-concept pairing lock.** Trigger: slot taps on `#/duel`. Rule: the left frame binds to `leftConcept`, right to `rightConcept` — labels travel with the slot into the strip; recapture of either side is always available before scoring and overwrites only that side's file. Gallery picking is an accepted source for either slot. Conflict: `USER_CANCELLED` leaves the slot unchanged; `PERMISSION_DENIED` / `CAMERA_UNAVAILABLE` never marks a side captured. Feedback: single-line English permission gate; slot shimmer on overwrite.
- **BR-05 — Contrast Score formula.** Trigger: “Score it” on `#/duel/board`. Rule: `base = round((ratingLeft + ratingRight) / 2)`; `balanceBonus = 10` when `|ratingLeft − ratingRight| ≤ 10`, else `0`; `contrastScore = clamp(base + balanceBonus, 0, 100)`. Grades: `S` ≥90, `A` 75–89, `B` 60–74, `C` <60. Conflict: rails default to 50/50; scoring is repeatable before vault — the latest score wins. Feedback: live score read-out while dragging; grade medal sheet after scoring.
- **BR-06 — Ring day state machine & streak.** Trigger: session mutations + local midnight rollover. Rule: today's segment `pending → in_progress` on first capture, `→ done` on first scored session; at midnight an unscored `pending/in_progress` day flips to `missed`. `currentStreak` = consecutive `done` days ending today (a still-open today counts the streak through yesterday); ring window = rolling 7 calendar days ending today. Conflict: multiple sessions share one day — the first scored session closes it, later ones only improve stats. Feedback: segment fills (done = solid fill + vault dot when vaulted), streak badge increments, missed day shows an outline crack.
- **BR-07 — Vault gate & caption.** Trigger: “Vault this pair”. Rule: only sessions with `contrastScore` ≥75 (grade S/A) expose the vault CTA; vault write is idempotent per `sessionId` (double-tap creates exactly one VaultPair). Caption: 0–50 chars, whitespace-trimmed; empty caption stays blank — never auto-filled. Conflict: re-vaulting an already-vaulted session is a no-op returning the existing pair. Feedback: toast “Pair vaulted into the Opposites Vault”, vault dot on today's segment.
- **BR-08 — Export quota & coin price.** Trigger: “Save to Photos”. Rule: first strip save per local day is free (`freeExportDateKey` = today after using); subsequent saves cost 25 coins each; coins are charged only after the B05+B02 chain succeeds. Conflict: insufficient balance → Store deep link (SW-B resumes at PW step 12); failure or cancel leaves quota and balance untouched. Feedback: quota chip on the save bar; coin confirm sheet shows price + resulting balance.
- **BR-09 — Export fidelity & persistence.** Trigger: strip save. Rule: export renders the SAME composition tree as the on-screen strip preview — same layout, same aspect (portrait 4:5), exported pixels = preview's rendered pixel size at the device pixel ratio; no post-render resampling, no re-layout, no blank-frame export. Persist to `strips/{YYYYMMDD}_{pairId}.jpg` via B05 before B02 album save. Conflict: a missing or unreadable source frame blocks export with an error state (never a partial strip). Feedback: progress veil during persist, success toast “Saved to Photos”.
- **BR-10 — Coin credit & ledger idempotency.** Trigger: StoreKit purchase callbacks + coin spend confirms. Rule: `earn_iap` entries dedupe on StoreKit `sourceTxnId` (one credit per transaction, replay-safe); spends validate `balance ≥ price` synchronously before mutation; every mutation appends a CoinLedgerEntry with the resulting `balanceAfter`. Conflict: cancelled purchases write nothing; failed purchases write nothing; an interrupted resume re-reads the ledger rather than trusting UI state. Feedback: success toast “+{n} coins — balance {b}”; silent dismissal on user cancel; English retry alert on real failure.

## Primary Workflow

“Wind the ring → shoot both opposites → score the contrast → vault the win → save the strip.”

1. **Launch & boot.** Shell shows LaunchScreen → LaunchVeil; WKWebView loads the H5 entry transparently underneath. H5 `boot()` runs immediately (no timers), hydrates stores (`dualoo.*` keys) and the seeded deck, fetches safe-area insets via B06 `getDeviceInfo`, paints splash, and fires B12 `shellReady` after a double rAF so the shell lifts the veil. Data: none mutated. Failure UX: shell retry page (English) on load error.
2. **Welcome gate (first run).** `#/welcome` shows three theme-fitted pages; both agreement links open `#/legal` as a bundled-text overlay layered over welcome. “Agree & Start” stays disabled until both documents were scrolled to end and the single checkbox is ticked; on confirm, `AppSettings.legalAcceptedAt` is set and the router lands on `#/ring`. Later runs skip welcome based on `legalAcceptedAt`.
3. **Ring home state.** `#/ring` renders the rolling 7-day DrillRingDay ledger (BR-06), a time-of-day scenario greeting, streak badge, and today drill card. If an active unfinished session exists, the card shows its pair and status instead of the draw hint (BR-03 groundwork).
4. **Wind-Up Draw (signature).** Press the ring centre, drag clockwise ≥180°, release — the ring springs back, a shuffle shimmer plays, and the antonym card flips out of the ring centre. Data: `DuelSession(status=drawn, dateKey=today)`, card `lastDrawnAt` stamped, `freeDrawsLeftToday` decremented per BR-02 (or the 12-coin sheet interrupts before creation). Feedback: flip animation + segment tick. (BR-01, BR-02)
5. **Enter the duel.** Tapping the fresh card pushes `#/duel`: prompt recap card on top, two labelled empty slots (“LEFT — {leftConcept}”, “RIGHT — {rightConcept}”) with a capture-from-camera default and gallery fallback per slot (BR-04). Resume sheet appears here first if BR-03 applies.
6. **Capture the left frame.** Tap the LEFT slot → B01 `pickImage {source:'camera'}`. Shell persists `frames/{sessionId}_L.jpg` into Documents and returns the relative path; H5 previews via `dualoo-asset://local/...`; status `left_captured`; `DrillRingDay(today)` → `in_progress` (BR-06). `USER_CANCELLED` keeps the slot empty; `PERMISSION_DENIED` shows the one-line gate (BR-04).
7. **Capture the right frame.** Same flow for the RIGHT slot → status `right_captured`; “Rate the contrast” lights up. Either slot can be recaptured any time before scoring (overwrite, BR-04).
8. **Rate on the Dual Rail Board.** `#/duel/board` shows both frames with the pair caption; two rails start at 50/50; dragging a rail re-renders the live Contrast Score preview per BR-05 (computed in memory, not yet persisted). Feedback: tick feedback at each decade; Live read-out “L 80 · R 80 → 100”.
9. **Score it.** Tap “Score it” → `contrastScore` + `grade` computed and stored (BR-05); session → `rated`; `DrillRingDay(today)` → `done`; streak and weekly completion recompute (BR-06). Feedback: grade medal sheet (S/A/B/C) with the score stamped under the frames. B/C grades show the coaching copy and direct “Re-shoot LEFT / Re-shoot RIGHT” shortcuts (re-enter PW step 6/7 with overwrite intent).
10. **Vault the win.** Grade S/A shows “Vault this pair” → BR-07 idempotent vault write (`VaultPair` created, session → `vaulted`, `vaultedAt` set). Feedback: toast “Pair vaulted into the Opposites Vault” + vault dot on today's segment.
11. **Open the strip.** From the vault toast or pair detail, tap “Make the strip” → `#/strip/:pairId` renders the export-identical Before–After Strip preview (BR-09): 4:5 portrait composition, both frames with concept captions, score stamp, date line.
12. **Save to Photos.** Tap “Save to Photos” → BR-08 quota gate (free today vs 25-coin confirm; insufficient → SW-B). On confirm: B05 `writeFile` persists the rendered strip to `strips/{YYYYMMDD}_{pairId}.jpg`, then B02 `saveImageToAlbum` copies it into the system album; `stripPath` stored on the VaultPair. Feedback: progress veil → success toast “Saved to Photos”; any failure leaves balance/quota untouched and keeps the Documents copy.
13. **Back on the ring.** Today's segment is solid (`done`) with a vault dot; streak badge reflects BR-06; the ring hints tomorrow's empty segment. The drill loop closes in under a minute.
14. **Hub destinations.** Tab bar reaches `#/vault` (revisit/curate, SW-A), `#/store` (coin top-up, SW-B), `#/settings` (drill slot preference, legal overlay, long-press version → hidden `#/plaza` Bridge smoke matrix).

## Secondary Workflows

### SW-A — Vault review & curation (8 steps)

1. Tab 2 `#/vault` loads vaulted pairs newest-first with the stat strip (current streak, weekly completion, 7-day average contrast) computed per Metrics. Empty first-week state shows the ring motif + CTA “Wind the ring to vault your first pair”.
2. Open the filter bottom sheet (hash overlay stacked over `#/vault`): filter by grade (S / A), deck (`core` / `senses_space`), month, favorites-only; apply re-renders the grid.
3. Zero-hit filter result shows the dedicated empty state “No pairs match — widen the month or grade” with a one-tap filter reset.
4. Tap a pair card → `#/pair/:pairId`: both frames, score, grade medal, deck + date, caption field.
5. Edit caption inline (≤50 chars, BR-07) → persisted on blur; tap “Copy caption” → B08 `copyToClipboard` → toast “Caption copied”.
6. Toggle favorite → the Favorites filter view and grid star update immediately.
7. Tap “Re-export strip” → `#/strip/:pairId` under the same BR-09 fidelity contract → BR-08 quota/coin rules apply → save via B05+B02 (deterministic filename overwrites the previous strip of the day for that pair).
8. Delete from detail: confirm sheet explains the frames stay on disk; on confirm the VaultPair is tombstoned (`trashedAt`) and a Snackbar offers Undo for 5 s; timeout removes it from every list and stat; Undo restores instantly. Return to `#/vault` re-computes stats.

### SW-B — Coin top-up & paywalled resume (8 steps)

1. Entry context: the coin sheet (draw quota out / export quota out) or Tab 3 hero balance on `#/store`.
2. `#/store` loads: balance hero, Standard zone (9 tiers), Limited Promo zone (6 tiers) — product ids, coin amounts, prices exactly per IAP Catalog below; skeleton shimmer while loading; “Restore Purchases” row at the bottom; lifetime earned/spent line from the ledger.
3. Tap a tier → confirm sheet shows product, price, coin amount, and post-purchase balance preview → tap Buy → B09 `purchase` fires; H5 shows the full-screen non-piercing coin-press loading veil.
4. Shell StoreKit success → BR-10 credit exactly once (txn-deduped) → success toast “+{n} coins — balance {b}” → ledger entry appended.
5. User cancel (`USER_CANCELLED`) → veil drops, no failure toast, balance untouched.
6. Real failure → English single-line alert + Retry; StoreKit unreachable (`IAP_UNAVAILABLE`) → error block with Retry on the store page.
7. If a pending intent exists (draw or export), the router pops back to the interrupted sheet automatically: e.g. “Spend 12 coins for this draw?” → Confirm → BR-08/BR-10 spend record → the original flow resumes at PW step 4 (draw) or PW step 12 (export).
8. Spend chain re-validates `balance ≥ price` at confirm time; on success the ledger appends `spend_draw`/`spend_export` with the resulting balance and the flow continues — no manual navigation needed.

## Bridge Capability Matrix

Channel names LOCKED: `dualooBridge` (H5→shell) / `dualooBridgeCallback` (shell→H5) — derived from the app name, never from the code prefix. Request envelope `{ id, action, payload }`; success `{ id, data }`; failure `{ id, error: { code, message } }`. ## Export / Save Flow

- **Fidelity contract (hard rule):** the exported Before–After Strip is rendered from the exact same composition tree as the on-screen preview on `#/strip/:pairId` — same layout, same order, same aspect (portrait 4:5). Export pixels equal the preview's rendered pixel size at device pixel ratio; there is no re-scale pass, no re-layout, no alternate “export skin”, and an export with a missing/blank frame is blocked per BR-09 instead of shipping.
- **Strip composition:** top band with the pair label “{leftConcept} ⟷ {rightConcept}” and the local date; middle with the LEFT frame and RIGHT frame split by the wobbly divider (orientation per design system); bottom band with the Contrast Score + grade stamp. Caption text only comes from explicit user input (BR-07) — never placeholder filler.
- **Save steps:** quota check (BR-08) → the coin confirm sheet shown when the free save is spent → render-identical persist via B05 `writeFile` to `strips/{YYYYMMDD}_{pairId}.jpg` → B02 `saveImageToAlbum` → toast “Saved to Photos” → `stripPath` set on the VaultPair.
- **Re-export:** deterministic filename per day+pair overwrites the previous day's strip file for that pair; quota rules apply on every save (BR-08).
- **Failure handling:** any failure in the B05→B02 chain shows the inline error state + “Save failed — retry” toast; balance and free quota are never charged for failed saves; the Documents copy stays available for retry.
- **Sharing:** happens from the system Photos app after saving; the app ships no outbound share sheet and no network calls.

#### 产品概述 (Product Overview)

Dualoo（反义对拍）是一款离线优先的「反义词对拍」轻练习 App：每天从题卡堆抽出一张反义词对（如 Wet ⟷ Dry），走出屏幕用相机分别为左右两边各拍一张实景，在双轨评分板上给两边的「对立强度」打分得到对照评分（Contrast Score），S/A 等级的「成对优胜」归档进本土对拍库（Opposites Vault），并可将成对作品一键排版为 4:5 前后对照贴图存入系统相册，用于词汇与构图反复演练。练习节奏由 7 天滚动「练习环」（Drill Ring）驱动：拧环抽签、当日完成、断签可见。全部数据仅存本机，无账号、无云同步、无社交信息流。

主要功能边界：不做社交关系链与关注/点赞；不做云端相册与跨设备同步；不做推送通知（练习提醒以 App 内练习环可视状态呈现）；不接入第三方统计/广告 SDK；除 App Store 内购与系统相机/相册能力外不访问网络与第三方服务。内购仅为消耗型金币（加抽、加导出），无订阅、无广告变现。

**差异化角度（PM Deck：`primaryUserGoal`）**

核心动作是「抽到反义词后立刻用实拍画面替抽象概念作证」，目标客户目标是用碎片时间把概念练成直觉。与拍照打卡、相册整理、闪卡背词类 App 不同：Dualoo 以「提醒环」组织练习节奏（T8 拓扑，非标签列表首页），以双轨量化「对立张力」而非简单收藏，产出物是可外发的对照贴图——一抽、两拍、一评、一贴，一局不到一分钟。

**受众与场景**

喜欢用拍照练概念的年轻人：语言学習者用对照画面巩固反义词；设计/摄影爱好者练构图与观察力；正念人群做一日一次的「对立刻意练习」。典型场景：通勤路上抽一张卡，午休各拍一张，回家路上评分入档，睡前把贴图存进相册周末回看。
